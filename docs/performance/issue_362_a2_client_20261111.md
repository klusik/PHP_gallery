# Issue #362: A2.1 client thumbnail diagnostic slice

**Status:** Implemented in the issue feature branch. The complete A2 milestone remains open. This is a bounded passive client sampling slice, not the server profiler, thumbnail-batch protocol or full route diagnostics.

## Runtime contract

The existing `_NativeGalleryViewer._observe_thumbnail_read()` receives immutable statistics from the real native read and network-free disk lanes. A small `ThumbnailPerformanceWindow` records only their existing `MediaReadTimings` numeric phase values and a fixed source code. It neither initiates new requests nor grants any cache authority.

- Capacity: at most **256 observations** in the most recent **300 monotonic seconds** per live viewer. Expired entries are removed on observation and snapshot.
- Source: `unknown`, `disk`, `network`, or `revalidated`. Never store gallery IDs, photo IDs, account identities, paths, arbitrary messages, hostnames, response bodies, tokens or request URLs.
- Counts: sampled read operations, actual HTTP send attempts, received bytes, and source classes. Cache-only local lookups remain separate from physical HTTP attempts. A disk miss followed by a network read is two read observations, not two HTTP requests.
- Distributions: nearest-rank p50/p95/p99 of gate wait, transport-slot wait and decode phases, and of the measured network/TTFB phase for reads with **exactly one** HTTP attempt. Multi-send/retried operations contribute to HTTP attempts but do **not** masquerade as a single-request TTFB sample. Empty distributions are `unknown`.
- The new bounded window appears as an additional safe line in the existing copyable Photos diagnostic snapshot; historical cumulative counters remain unchanged. UTC interval labels describe the window at export time, while inclusion/expiry uses a monotonic clock.
- The read outcome remains **unknown** if the existing validator has not produced a recognized source. This initial slice does not claim reliable per-request HTTP status, failure-stage, full user-visible elapsed time or host-side PHP timing.

## Qualification

`.github/workflows/issue-362-a2-client-diagnostics.yml` runs portable Python 3.14 unit tests on **GitHub-hosted Ubuntu and Windows** whenever the first-slice implementation changes, and has an optional manual dispatch. Test coverage includes empty intervals, exact nearest-rank percentiles, physical request counts, cache-only reads, retries, sample limit, expiry, non-finite/unsafe input and concurrent producers. It also compiles the modified viewer source without opening a physical GUI.

## A2.2: linked HTTP route outcome diagnostics

The next small slice adds `linking_performance.py` and wires it to the existing session's authenticated JSON and native media transport owners. Each `LinkingSession` owns one **300-second / 256-operation** rolling window with strictly allowlisted categories (`gallery_tree`, `gallery_page`, `media_page`, `thumbnail_single`, `revision`, etc.), numeric statuses, fixed reason codes and client-side elapsed p50/p95/p99. Explicit unknown status and unknown physical send count are retained when the transport has no defensible proof. A `200` or conditional `304` is only recorded after the existing media validation succeeds; actual `401/403/429/502/503` refusals keep their safe error classes. Native media sends are counted from **per-operation deltas** of existing `MediaReadTimings.http_requests`. An unmetered reused socket can retry, so its send count stays unknown instead of being guessed.

The copyable Photos diagnostics now includes the session's safe, bounded route summary alongside the existing A2.1 thumbnail and lifetime counters. This does not enable polling, change credential or cache authorization, alter rate limits or modify network admission. The client-side operation intervals cannot be interpreted as PHP execution time, provider worker availability or a host-wide request trace. The optional server profiler, tree fallback timing and complete A2 acceptance remain separate work.

CI includes focused cross-platform tests of both A2 modules and mocked *actual LinkingSession dispatch boundaries*. The mocks do not establish live HTTP interoperability; the A1 owned PHP/MariaDB transport and complete Windows Tk matrix remain separate full-qualification owners.

## A2.3: catalogue tree/legacy fallback and Tk phase evidence

The third isolated A2 slice adds `photos_catalogue_performance.py` and keeps the existing `PhotosWorkspace` tree-v1 protocol, display-only DPAPI snapshot, 50-row pages and 64-row/16-ms Tk mounting rules unchanged. All phases use a **300-second monotonic, 256-entry** fixed-label numeric history with nearest-rank p50/p95/p99 and separate, resettable current-catalogue-pass facts.

The existing catalogue worker measures real local cache load/decrypt/parse as **one combined worker interval** when it actually attempts a local snapshot, and real `session.gallery_tree()` or `session.gallery_page()` operation duration separately. It attaches optional numeric durations and a static cache/fallback label to the **existing generation-fenced worker results**. Only the Tk owner observes accepted, same-session, non-cancelled results. Observations distinguish retained display metadata, verified disk snapshot, miss/disabled cache, accepted `tree-v1-full` and `tree-v1-unchanged`, optional `paged-fallback`, admitted legacy page count, genuine tree errors/429, and per-slice cached/fresh Tk mounting and page reconciliation.

A cached row never becomes a fresh grant: `cache_source` is separate from `transport_source`. When the optional tree path returns `None`, the only defensible fallback reason is `optional_unavailable`, not a fabricated HTTP 404/503. A missing capability is `capability_missing`; a failed/rejected tree does **not** masquerade as successful pagination. Missing timing appears as `unknown`. The retained rolling samples remain bounded across manual refreshes, while current pass counters reset. There are no raw galleries, filenames, response bodies, tokens, identifiers, file paths or URLs in diagnostics.

The safe catalogue summary is appended to the existing copyable Photos diagnostics. Focused portable tests validate source semantics, current-pass reset, page/row counts, percentile behavior, capped retention and rejecting unsafe labels. Existing GitHub-only Ubuntu/Windows workflow checks this plus previous A2 tests and compiles the real Photos workspace. Linux/Windows unit tests are not a physical-screen or WEDOS production benchmark, and the remaining full integration matrix is still mandatory.
