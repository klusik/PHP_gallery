# Issue #362: A2.4 passive PHP request profiling

**Scope:** A small, explicitly opt-in server-side diagnostic slice built on A2.1 through A2.3. It is not full A2 acceptance, a new public API, a host worker sampler or a production deployment.

## Runtime and security contract

The native API PHP profiler is defined in `app/services/app_linking_passive_profile.php`. It is **off by default** and can be enabled only by the server-side process environment:

```text
PHP_GALLERY_A2_PASSIVE_PROFILE=1
```

No query argument, request header, public diagnostic route or browser request can enable it. The request-local state lives only in PHP memory. It does not schedule HTTP requests, allocate a persistent log, launch a process, take a global lock, create a shared cache or require cron. Each request has fixed route/phase labels, a hard ceiling of 512 observed SQL executions and an explicit truncation bit, a 64 MiB cap on accounted hash bytes, and a 600-second per-phase sanity bound. SQL text, SQL parameters, exceptions, issuer values, gallery identities, filesystem paths, tokens and response bodies are never retained.

The PHP controller begins sampling only after the existing canonical route/query validation. It marks the sample authorized only **after** the established live bearer, scope and gallery/thumbnail authority checks have passed. The response obtains a `Server-Timing` header only on that authorized path, never on an anonymous 401 or an Admin-only 404 refusal. The fixed-value header includes numeric `gallery-php`, `gallery-sql`, `gallery-auth`, `gallery-tree`, `gallery-hash`, `gallery-media` durations and bounded `n`, `max_ms`, `failed`, `cap` and hash-byte descriptions. No full request metadata is exposed.

Existing grant revocation, public/Admin/NSFW, path containment, ETag/304, rate limit, photo-cache headers, binary body and HEAD behavior retain their normal owners. The API has **no** new permission scope, endpoint, table, cookie or bearer representation.

## Measurement boundaries and interpretation

- The canonical `TelemetryPDO` dispatch already measures prepared `execute()`, direct `query()/exec()` and other supported database operations. A2 adds only a numeric subscriber. Its count is **observed executed database operations**, not all SQL statements the host may execute, and includes any observed transaction operations. It reports total, maximum, failed and whether the fixed cap was reached; it records no query text.
- `gallery_model` measures the tree model call, which **includes SQL time**. `tree_json` measures revision JSON encoding and `tree_hash` the subsequent SHA-256 calculation. The `gallery-tree` header is a sum of these tree subphases, **not** an additive decomposition with `gallery-sql`, since the SQL observer overlaps the model interval.
- `media_metadata` measures authorized native metadata generation; `photo_open` measures resolving/opening a currently approved binary file, including validator preparation. `file_hash` measures actual `hash_update_stream()` work and counts bytes that were passed to SHA-256. It does not claim additional content was downloaded or generated by the visitor.
- `gallery-php` measures the interval **from profiler initialization until the response header is prepared**, not the full PHP bootstrap, subsequent `fpassthru()` stream, upstream proxy delay or total client TTFB. Process peak memory, when inspected in PHP, is local and does **not** disclose other sites, pre-PHP queueing or available WEDOS worker slots.
- The optional `Server-Timing` header is measured on the owned GitHub loopback server. Whether WEDOS or its protection gateway preserves it is **UNKNOWN** until approved hosted staging verification. It should not be treated as a reliable cross-host duration or a substitute for independent server/proxy logs.

## GitHub-only qualification

The existing `.github/workflows/issue-362-a2-client-diagnostics.yml` has isolated Ubuntu PHP **8.1** and **8.5** jobs, each using a fresh MariaDB **10.11** service. The tests execute without a local user computer and without WEDOS network traffic. The temporary `GalleryWorkflow\\Fixture` copies the application, runs actual migrations, seeds synthetic public and protected galleries and real tiny JPEG images, and provisions an ephemeral bearer grant. All credentials remain in isolated process memory or private temporary fixture resources which are deleted afterward.

`tests/app_linking_passive_profile_test.php` verifies off-by-default behavior, strict server-side enabling, route allowlists, missing authorization, numeric-only PDO observations, response formatting, SQL cap/truncation and per-request reset.

`tools/perf/issue_362_a2_php_http.php` sends actual loopback HTTP requests and verifies the relevant result and restricted timing behavior: unauthorized tree **401 without timing**, read-only Admin revision **404 without timing**, authorized full and unchanged trees **200**, paginated gallery listing **200**, photo metadata **200**, real thumbnail **200** with nonzero hashed bytes and conditional thumbnail **304**. It also refuses route redirects and malformed synthetic selectors. The retained GitHub artifacts contain only sanitized result statuses, exact source SHA and scope limitations, not secret tokens, response bodies, gallery titles or SQL. The tests do not run the existing cache-clearing Admin Test Run.
