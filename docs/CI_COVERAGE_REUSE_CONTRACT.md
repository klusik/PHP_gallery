## Authority and evidence

The manual integration workflow runs from protected main source W, distinct from
S/A. Privileged jobs check out W only; candidate generation and FULL jobs have
read-only permissions and no persisted write credential. Generated bytes cross
the boundary as bounded, provider-digest-verified data. Only
`app/runtime/modules.php`, `app/production-files.json` and `app/core-manifest.json`
may change during preparation. With `auto_squash_generated` enabled (default),
the API publisher creates A with the prepared tree and sole parent P, preserves
the complete source message and adds `Prepared-From: S`. It updates only the
selected feature ref through GraphQL `updateRefs`, binding `beforeOid=S`,
`afterOid=A` and `force=true`; a mismatched old head refuses the replacement.
The publisher rechecks P and reads the resulting feature ref. Protected develop
publication remains a non-forced fast-forward. Recovery and authority-update
dispatches do not use automatic rewriting.

Because token-originated ref updates do not start push-triggered BASIC, the
publisher explicitly dispatches `candidate-preparation.yml` with
`maintenance_full=false` and `return_run_details=true`. It polls the returned
run ID every five seconds for up to fifteen minutes, binding workflow path,
branch, SHA and first attempt. Failed/cancelled runs, changed refs, missing native
or custom evidence and superseding runs block FULL. Successful completion uses
the existing source selector and check/suite authentication again. The publisher
outputs final source SHA, BASIC run and attempt together; FULL and the final
integration publisher consume these outputs. The retained record therefore
binds BASIC and FULL to A, with S retained in the commit provenance. No generated
change means no rewrite or additional BASIC. Disabled automatic mode retains
the generated child and manual squash/fresh-BASIC checkpoint.

Provider interfaces: [conditional GraphQL ref updates](https://docs.github.com/en/graphql/reference/git#updaterefs)
and [workflow dispatch with returned run details](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

This feature requires hosted maintenance qualification and maintainer-controlled
installation on main before the integration button can exercise it. A feature

are not installation evidence; validate a real generated delta after installation.

from `candidate-preparation.yml`; it never publishes the FULL context.
